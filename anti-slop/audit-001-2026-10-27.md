# antislop audit 001, Hakiki web (`web/`), 2026-10-27

Mode: AFTER (session choice). Nothing has been changed. Pick numbers to fix; unlisted numbers are not touched.

## How this audit was done, and its limit

- Method: I read the code (layout, home, About, check, ask, section page, `globals.css`, `Checker.tsx`, `Ask.tsx`, most of `AnswerView.tsx`, parts of `Lineage.tsx` and `illustrations.tsx`), ran greps over `app/`, `components/`, `lib/`, and computed contrast with `antislop-human/contrast-check.py`.
- **I did not build or run the app, click through it, or resize a viewport.** Per R-35, every mobile, keyboard and state finding below comes from code reading and is marked *(code only)*. Items marked *(verify)* need a person or a browser run to confirm.
- Not read in full: `SectionList`, `SectionMeta`, `Specimen`, `court.tsx`, `StatuteText`, `VersionRail`, `Citations`, `History.tsx`, `useChats.ts`, `app/acts`, `app/search`, `lib/*`. Absence of findings there means "not looked at", not "clean".
- Direction: no `DESIGN.md`. Direction exists in practice (paper/ink/court palette, serif for law, serif italic on highlighter for the court's words, sans for ours; `web/components/illustrations.tsx`, `Stamp`, `Seal`, `Lineage`) and in the repo CLAUDE.md UI rules. Inferred dials: ENERGY 2 / RHYTHM 2 / MOTION 3. These are not written down anywhere (see #22).
- Priority follows tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW.

## HIGH (Hard Gate)

**#1 · R-02 · Em dashes in user-facing text.**
`app/ask/AnswerView.tsx:137` ("Not in Hakiki's collection, [em dash] check before relying on it") and `:138` ("Could be more than one case ... [em dash] check which one is meant"). These are the only two in rendered UI strings. Fix: a colon or period.
Related, not UI copy: `lib/text.ts:37` and `:38` write and match an em dash when repairing statute text (`'at any time- (a)'`). That is data repair of the law's own text, so R-02 arguably does not apply. Flagging so you decide, not me (R-37 style: name it, ask).

**#2 · R-32 · Focus indicator removed with no real replacement.**
- `app/check/Checker.tsx:155`: the filing textarea has `focus:outline-none`, no border, no ring. The whole sheet gives no sign it has focus. *(code only)*
- `components/Lineage.tsx:118`: every lineage node link has `outline-none`, which overrides the global `:focus-visible` rule. The only focus signal is that other nodes dim to 0.35 opacity. Weak, and not the 3:1 indicator R-32 asks for.
- `components/illustrations.tsx:37`: the Acts shelf links have `outline-none`; the only focus signal is a 4px, 4 degree lean of the spine (`globals.css:150`). Same problem.
Fix: remove `outline-none` on the two links (the global 2px gazette outline then applies) and give the textarea a visible focus style such as a ring on its wrapper.

**#3 · R-03 · Tap targets under 44px.** *(code only)*
- Mobile search link: icon only, `h-5 w-5` = 20px (`app/layout.tsx:75`).
- Theme toggle `h-9 w-9` = 36px (`ThemeToggle.tsx:32`).
- Header nav links are bare text at 0.95rem, about 24px tall, `gap-4` apart (`layout.tsx:57`).
- Ask: "New chat" / "Your chats" (`py-1.5`, text-sm, about 32px), Answer/Draft toggle (`py-1`, about 28px), Copy/Word/PDF buttons (`py-1`, about 28px), History close (`py-1`), send button 40px (`Ask.tsx`, `AnswerView.tsx:113`, `History.tsx:137`).
Fix: pad hit areas to 44px minimum (padding or `min-h-11 min-w-11`) and keep gaps between neighbours.

**#4 · R-03 · Header likely does not fit a 360 to 375px phone.** *(verify)*
One row holds the seal (32px), "Hakiki", four nav links, the search icon and the toggle. Rough sum is above the 320 to 335px available after `px-5`. This is the "Nav That Stays Desktop" tell. Measure at 360 and 375 before choosing a fix (menu, or fewer items shown).

**#5 · R-03 · The "Upload PDF or DOCX" button is pushed off-screen on phones.** *(code only, verify)*
`Checker.tsx:73` to `:100`: the exhibit tabs, the "Synthetic examples" label and the upload button share one `overflow-x-auto` row, and the upload button is `ml-auto` at the far end. On a phone the user's own filing, the main use, sits behind a sideways scroll with no cue.

**#6 · R-27 · Missing failure and loading states.**
- `Checker.tsx:64-68` `loadExhibit`: `await (await fetch(...)).text()` has no `res.ok` check and no `catch`. A failed or 404 fetch writes an error page's HTML (or throws) into the filing box. Real bug.
- `Checker.tsx:36-55` `readFile`: `await readFiling(form)` is not in a try/catch. If the server action throws (network drop, 4 MB Vercel body limit hit), `setReading(null)` never runs and the "Reading file..." overlay stays up for good.
- Only `app/p/[...id]/loading.tsx` exists. Home, Acts, Search and About await the API and have no loading UI (`find app -name loading.tsx`). *(verify how slow they feel on a cold Railway API)*
- `app/error.tsx` shows end users a developer instruction ("Running it locally? Start the API ... `uv run uvicorn api.main:app`") and the words "The citator's database didn't answer". It names the cause but speaks to the author, not the visitor. It also ignores the `error` prop (no logging).

**#7 · R-36 · Claims to verify before they stay.**
- `app/check/page.tsx:17`: "Your text or file is checked and thrown away. Nothing is stored." I cannot verify this from the web code. The text passes through a Vercel server action, Railway, and possibly OCR, and either host may log request bodies. If it cannot be proven for every layer, soften it to what is true ("Hakiki does not save your filing").
- `app/ask/page.tsx`: says an AI model writes the answer, but not that the question goes to an outside model provider (CLAUDE.md names Gemini). Lawyers ask about live matters. A one-line disclosure is the honest version.
- `app/layout.tsx:87`: footer says "Kenya Law (CC BY-NC 4.0)". CLAUDE.md records legal advice that the data may be used non-commercially, and does not quote that licence. Check the licence name against the source.
- `app/about/page.tsx:132`: "every ruling it accepted was right". The benchmark is 59 of 59 accepts on a sample of 111 events. Say "all 59 it accepted in that sample"; "every" reads as a general guarantee.

**#8 · R-35 · No recorded click-through.** This audit is code reading only (see top). Before the fixes ship, someone runs the build, tabs through every page, and records element by element results at 360, 768 and 1280 widths in both themes.

## MEDIUM (Purpose-Gate)

**#9 · R-25 (non-text) and R-25 (text) · Contrast.**
Computed with the checker script:

| Pair | Ratio | Result |
|---|---|---|
| ink-2 on paper (light) | 6.33 | pass |
| ink-2 on panel (light) | 5.80 | pass |
| gazette on paper | 7.11 | pass |
| seal on note | 7.50 | pass |
| dark: ink-2, gazette, seal on note | 7.95, 9.12, 6.54 | pass |
| **placeholder `text-ink-2/70` on paper (light)** | **3.24** | **fail (needs 4.5)** |
| placeholder `text-ink-2/70` (dark) | 4.54 | borderline pass |
| **input / composer borders `border-rule` on paper** | **1.41 (light), 1.65 (dark)** | **fail 3:1 for component boundaries** |
| stamp border `border-ink-2/50` | 2.21 | fails 3:1, but the stamp also carries text |

`placeholder:text-ink-2/70` appears 13 times. Search box, section filter and Ask composer rely on a 1.41:1 hairline to show where the field is. Fix: drop the `/70`, and use `border-ink-2` (or a darker rule token) on inputs and the composer.

**#10 · R-04 · Icon set and a generic fallback.**
`lucide-react` is imported in 8 files (Ask, AnswerView, History, layout, court, SearchBox, Citations, ThemeToggle). Meanwhile the house identity is hand-drawn SVG (Seal, Stamp, KindIcon, Lineage, illustrations). Two icon languages in one product, and the thin Lucide stroke is the "library look" tell. Specifically `AnswerView.tsx:221` falls back to **`Sparkles`** for any unknown tool, which is the generic AI glyph. Minimum fix: replace the `Sparkles` fallback with no icon. Fuller fix: draw the dozen icons in the house style. Written relevance for the rest (Gavel for a case, Search for search) is fine.

**#11 · R-01 / R-29 · Seal (crimson) is used for decoration, which dilutes its meaning.**
Seal marks "a court acted" (stamps, flagged citations, errors). It is also used for:
- the status names in About's glossary (`about/page.tsx:107`, `text-seal`),
- every benchmark score on About, "132 of 139" and "46 of 50" (`:158`), which read as warnings though they are good results,
- the left stripe on the Ask disclaimer (`ask/page.tsx:16`, `border-l-2 border-seal/60`, a Colored Left Stripe with no state behind it),
- the "over the limit" counter and error text, which is correct.
Chromatic colours in play: gazette green, seal crimson, mark yellow, plus the cream note. That is at the R-29 ceiling, so each must mean one thing. Suggest: scores and glossary labels in ink, keep seal for "court acted" and errors only.

**#12 · R-19 · Motion: declared dial missing; one reduced-motion hole.**
About 25 keyframe animations across the site. Most are on-theme (stamp, pinned note, sheet feed-in) and each has a comment saying why, which satisfies R-19's "purpose written down". Issues:
- `Checker.tsx:167`: the submit icon uses Tailwind `animate-spin`, which is not covered by the hand-kept `prefers-reduced-motion` block in `globals.css:344`. `AnswerView.tsx:115` correctly uses `motion-safe:animate-spin`. Make them match.
- Three infinite loops (`.scan::after`, `.drop-hint`, `.step-now svg`) are tied to a live state (reading, dragging, working), so they are acceptable. They are all listed under reduced motion. Good.
- The reduced-motion list is a manual allow-list; the next new animation will be forgotten. A single `@media (prefers-reduced-motion: reduce) { * { animation: none !important } }` plus the few final-state exceptions would be safer. Your call.

**#13 · R-20 / R-30 · The Ask page drifts toward a generic chat UI.**
Pill chips (`rounded-full`), a round `ArrowUp` send button, a pill Answer/Draft toggle, and a speech bubble with a tail. Everywhere else the product is square-cornered paper (`rounded-sm`, `rounded-md`, rules, stamps). Ask has the nicest paper touches (draft sheet, history sheet), but its input row looks like every chat product. R-11 is not broken (radius is not uniform site-wide), but the pill shape is concentrated in the one place that looks cloned. Suggest a rectangular composer with a labelled "Ask" button and note-style chips like the Checker's exhibit tabs.

**#14 · R-12 · Shadows hard-code a light-theme colour.**
Seven arbitrary shadows use `rgba(24,33,43,...)` (Checker sheet, report page, notes, candidate cards, draft paper). The elevation reason is real ("paper on a desk"), so R-12 passes. But on the dark `#141a20` page the shadow is invisible, so dark mode loses the lift (R-34, minor). Put the shadow colour in a CSS variable that changes with the theme.

**#15 · R-26 / C-2 · Interactive elements I could not confirm.** *(verify)* On the click-through: exhibit tabs load text; upload opens the picker and also accepts drops; "Show unverified leads" toggles; "Ask again" retries; Copy / Word / PDF; History sheet closes on Escape (native `<dialog>`, probably yes); mark links `#f0` jump to the note. Nothing looked dead in the code, but none was exercised.

## LOW (Quality Locks and copy)

**#16 · Copy · Actorless passive and a human verb on a thing.**

**#17 · Copy · Aphorism and filler.**
- `about/page.tsx:87`: "Treat leads as leads." is a formula that says nothing the next sentence does not. Suggest "Leads are not checked."
- `about/page.tsx:92`: "Or just ask." Drop "just".

**#18 · Copy · Bold run-in headers on lists.**
`about/page.tsx`: seven "How to use it" steps and five "Where the information comes from" items each start with a bold phrase and a colon or full stop. For the numbered steps, the bold lead works as a skim aid; for the Sources list it is the Inline-Header List pattern. Suggest keeping the steps, plain text for Sources. Low value either way.

**#19 · Copy · Jargon on the error page.** "The citator's database didn't answer" uses a word the visitor may not know. Pair with #6.

**#20 · Code · Benchmark numbers hard-coded in two places.**
"four in five" appears in `about/page.tsx:139` and `p/[...id]/page.tsx:181`; "111 events / 59 of 63" and the checker scores (`CHECKER_SCORES`, 8 rows) are literals in source. They match CLAUDE.md today but will not move when the benchmark is re-run. Move to one constants file (or the `/api/stats` response) with the file they come from named next to each.

**#21 · Code · Size and repetition.**
`Checker.tsx` (478 lines) holds the form, report, case, quote and section views and inlines four SVG icons (paperclip, magnifier, link, flag pin) next to a `KindIcon` that already exists. `layout.tsx` repeats the same title and description three times (default, openGraph, twitter). `MAX = 200000` and the 4 MB limit in `Checker.tsx` duplicate server limits. None is a bug. Pull the repeated metadata into one constant; leave the rest unless the file grows.

**#22 · R-37 / Block 3 · Dials and Design Read are not written down.** Add a `web/DESIGN.md` (even ten lines) with the palette meanings, type roles, and the dial line `ENERGY 2 / RHYTHM 2 / MOTION 3`, so future changes (and agents) have the direction the CSS comments only imply.

**#23 · Small type.** 12 uses of `text-xs` (12px) on labels such as "Exhibit A", legends and tags. Contrast passes and rem sizing zooms, so this is only a readability note. Raise to `text-sm` where the label is the only way to tell two controls apart (the exhibit tabs).

## Checked, no finding

- **R-17 / R-18 / R-38:** no invented numbers, testimonials, logos, avatars or team. The stats come from the API; the benchmark figures are real (see #20 for upkeep). Demo filings are labelled "Synthetic examples, written by us".
- **R-24:** nav is Acts, Check a filing, Ask, About. All four exist, plus the search page.
- **R-28:** no FAQ.
- **R-05 / R-14:** home is hero specimen, a ruled list, then an illustrated shelf. No hero + 3 cards, no bento, no logo bar, no 4-column footer (the footer is one paragraph). Content pages repeat one section pattern on purpose (RHYTHM 2).
- **R-06:** IBM Plex Sans and Newsreader, with the reason written in `globals.css` (law in serif, court in serif italic on highlighter, ours in sans). No uppercase tracking, no mono headings.
- **R-07 / R-13 / R-10:** no background grid (the grain and ruled paper are the identity motif and are explained), no glow, one blurred element (the sticky header).
- **R-15:** CTAs are specific ("Check citations", "Browse the Acts", "Ask again"). No buzzwords found by grep (seamless, powerful, unlock, and so on).
- **R-21 / R-34:** a working light and dark toggle with token overrides; colours I computed pass in both. Dark shadows are #14.
- **Decorative emoji, status dots, capsule badges above the H1:** none.
- **Skip link, `lang`, semantic landmarks, `aria-live`, `sr-only` labels:** present. Drag-and-drop has a keyboard route (the upload button).
- **antislop-code:** comments are overwhelmingly why-comments with specifics (limits, race conditions, tested behaviour). A few `globals.css` blocks narrate an animation's sequence in two to three lines. Not worth changing.
